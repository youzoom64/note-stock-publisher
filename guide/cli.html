CLIの使い方と実行前の準備

通常の利用はGUI・Discordで行えます。CLIは別ツールから呼び出すときの入口です。アプリのフォルダーを作業場所として、セットアップ済みの専用Pythonを使います。

runtime32\python\python.exe -B main.py --cli status
runtime32\python\python.exe -B main.py --cli list --output articles.json

--data-dirを省略すると通常のdataを使います。別のデータを指定する場合は、目的のフォルダーを明示します。読み取りの確認でも出力先には記事本文や設定が含まれる場合があります。

引数と戻り値

引数意味
--cli操作名
--id対象記事ID。job操作ではジョブID
--input入力JSONのファイル。UTF-8／UTF-8 BOM付き
--output結果JSONの保存先
--request-key同じ非同期要求の重複受付を防ぐキー
--data-dir使用するデータフォルダー

結果のokを確認します。失敗はerror、処理の受付や結果はresultに入ります。コンソールを持たない実行では、指定した出力先またはdataのcli-result.jsonを確認します。

記事IDと現在値を取得する

runtime32\python\python.exe -B main.py --cli list --output articles.json
runtime32\python\python.exe -B main.py --cli get --id ARTICLE_ID --output article.json

ARTICLE_IDはlistの結果にあるアプリ内の記事IDへ置き換えます。noteの記事URLの文字列と取り違えないでください。getの結果には、現在のupdated、タグのtags_revision、状態、予定などが含まれます。

非同期操作は受付と完了を分ける

sync_articles、save_note_draft、refresh_article、schedule、cancel_schedule、publish_note、delete_note、tagsなどは処理要求を受け付けます。操作名によっては公開CLIへ出していないものもあるため、下の操作一覧を使ってください。

runtime32\python\python.exe -B main.py --cli sync_articles --request-key sync-example-001 --output accepted.json
runtime32\python\python.exe -B main.py --cli job --id JOB_ID --output result.json

受付結果のjob_idで結果を取得します。状態はwaiting／running／done／failedです。受付に成功してもnoteへの保存・公開の完了ではありません。処理するPCアプリを起動しておく必要があります。

同じ処理の通信上の再確認には同じrequest-key、新しい意図の操作には別のキーを使います。アプリから応答がない場合は、自動で同じ投稿・削除を再実行しないで結果を確認します。

日時指定・取消のJSON例

まずgetで対象の状態と最新のupdatedを取得します。予約日時は未来の日時に置き換え、タイムゾーンを含めます。下は日本時間の例です。

{
  "due": "2026-12-01T09:00:00+09:00",
  "confirmed_updated": 1700000000.0
}

上の「1700000000.0」は説明用の表記です。実際のJSONではgetの数値へ置き換えてください。

runtime32\python\python.exe -B main.py --cli schedule --id ARTICLE_ID --input schedule.json --request-key schedule-example-001 --output accepted.json
runtime32\python\python.exe -B main.py --cli cancel_schedule --id ARTICLE_ID --request-key cancel-example-001 --output accepted.json

日時の登録と自動投稿の動作状態は別です。予約一覧を確認し、必要ならresumeを使います。過去の日時、noteへ未保存の記事、処理中・結果未確認の記事などは受け付けられません。

設定を変更するJSON例

{
  "article_sync_minutes": 60,
  "recurrence": {"days": [0, 1, 2, 3, 4], "time": "09:00"},
  "favorite_tags": ["日記", "読書"],
  "diagnostics": true
}
runtime32\python\python.exe -B main.py --cli settings --input settings.json --output settings-result.json

曜日は月曜0〜日曜6です。設定APIの対象はaccount、browser、note_login_method、article_sync_minutes、recurrence、favorite_tags、diagnosticsです。GUIにあるすべての設定名を、そのままJSONへ入れられるわけではありません。

アカウント・ブラウザーの変更は接続確認を外し、自動投稿を停止します。一部だけ保存できなかった場合は、エラーにある項目ごとの結果を確認します。

タグ・差し込み日の更新

tagsの入力は、タグ文字列とgetで取得したタグの更新番号を使います。下の例の1は、実際のtags_revisionへ置き換えてください。古い画面の値で上書きしようとすると拒否されます。

{"tags": "#日記 #読書", "tags_revision": 1}

recurring_overrideはキュー記事の差し込み日を扱います。{"day":"2026-12-01"}のような日付で指定し、{"day":null}で差し込みを解除します。日付は未実行の定期投稿枠へ置き換えてください。

投稿・削除を外部ツールから行う場合

publish_noteとdelete_noteには、直前のget結果のupdatedをconfirmed_updatedとして渡します。記事名・投稿先・本文・公開条件または削除対象を、呼び出し元で利用者に確認してください。

取得後に記事が変更されると古い確認は受け付けられません。公開結果が不明な記事には自動再送を行わず、note側の結果とverifyを確認します。変更あり・要確認の記事を、確認を省略して公開するための回避用APIとして使わないでください。

公開CLIの操作一覧

分類操作名用途
読み取りstatus / list / get / export / job状態・記事・保存済みデータ・受付結果を読む
原稿create / update / duplicate / delete / movePC内の原稿、変更した項目の保存、複製、未紐付け原稿の削除、手動順の移動
note操作要求sync_articles / save_note_draft / refresh_article / schedule / cancel_schedule / publish_note / delete_note / tags一覧同期、下書き保存、読み直し、予約、公開・削除などの要求
定期投稿recurring_overrideキューの個別の差し込み日
全体settings / pause / resume / discord設定、自動投稿、Discordの状態や連携操作
従来の画面操作login / edit / drafts / import / publish / verify接続、編集、下書き一覧と取り込み、投稿、結果確認。通常の外部連携は上の明示的な要求を優先

moveのdirectionは-1か1です。create/updateのstatusはdraft／queued／scheduledが対象ですが、note未保存の記事はそのまま予約済みにはなりません。画像ファイルはimage_file、記事のタグはtagsなど、変更する項目だけを渡します。未対応のキーや古い更新番号は受け付けられません。

従来のdeleteは、noteに紐付いた記事の削除ではありません。note上の記事にはdelete_noteを使います。従来のpublishなどを、呼び出し元の確認を省略する目的で使用しないでください。

Discord連携のCLI操作

--cli discordは、入力のactionでstatus／setup／enable／disable／menuを扱います。status以外はPCアプリの起動が必要です。たとえば{"action":"status"}で設定有無・接続状態を調べます。

menuは実際に管理チャンネルへメニューを送ります。setupは設定画面を開き、enable/disableは連携の有効無効を変えます。単なる接続検査のつもりで送信や設定変更を実行しないよう、actionを区別してください。
