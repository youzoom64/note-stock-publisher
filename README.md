# noteストック 2.0.0-rc1

Windows 11 x64のPCで起動し、スマホのDiscordからnoteの記事を管理するアプリです。独自EXEは作成・同梱しません。ChatGPTの契約・APIキー、クラウド、ポート開放は不要です。

## 初回セットアップ

1. 未使用の配布ZIPを、書込み可能なフォルダーへ展開し、`setup.cmd`を開きます。
2. セットアップが対応Python、専用仮想環境、ライブラリ、ブラウザーを確認します。Pythonがなければ公式署名を検証したインストーラーで導入します。PATHや既定のPythonは変更しません。展開先が長すぎる場合は短い保存先を選べます。
3. 最初に「Discord連携しますか？」と表示します。直後に「連携を使うと、iPhoneやスマホを使用して外出先から操作できます」と案内します。「今は使わない」ならBot作成や接続を開始しません。後から「Discord・セットアップ」で変更できます。
4. 「使う」場合は「専用サーバーを新規作成する」「既存のサーバーを選ぶ」を選びます。「よく分からない場合は、新規作成を選択してください」と表示します。新規ではサーバー名を入力します。既存ではDiscordの導入画面で管理権限のあるサーバーを選びます。候補が1つでも勝手に選びません。
5. セットアップ画面で規約を確認し、同意して開始します。本人のDiscordへログインすると、Bot作成・暗号化保存・選択したサーバーの作成／導入をアプリが実行します。二段階認証・CAPTCHAが出た場合だけ本人が完了します。新規サーバーの場合は、別端末で導入を承認してもBotの参加を検知して続行します。導入後は自動接続し、本人専用の「アプリ管理」カテゴリと「note管理」チャンネルを準備します。
6. PCの「設定」で本人のnote IDとログイン方法を選び、「ログイン・接続確認」を実行します。Googleの場合は通常の専用Chrome／Edgeで「Googleでログイン」を選びます。ログインできたらその専用ウィンドウを閉じると、アプリがnote IDを照合します。初回の本人ログインはPC上で必要です。確認が通るまでは記事の同期・予約投稿を利用できません。

セットアップを中断した場合は「Discord・セットアップ」タブから再開します。作成済みBotを再利用し、無関係なBotの設定やトークンを変更しません。開発者ページの構造が変わった場合は停止工程を表示します。

後からは同じタブの「Discord連携」チェックボックスで切り替えます。未設定でチェックを入れると、初回と同じセットアップ画面が開きます。設定済みなら保存した設定で接続し、外すと連携を停止します。導入先の変更は「Discord連携を設定・変更」から行えます。

CLIでも `main.py --cli discord` で連携状態を確認できます。起動中アプリへ `--input` のJSONで `{"action":"setup"}`、`{"action":"enable"}`、`{"action":"disable"}` を渡すと、同じ設定画面の表示・有効化・停止を実行できます。接続トークンは返しません。

普段の起動は `start.cmd` です。PCの電源・アプリ・ネット接続が必要です。PC停止・スリープ中はDiscord操作も予約投稿も動きません。Discordの接続だけが切れた場合、PCで受付済みの予約は継続します。

## Discordから使う

専用チャンネルに「メニュー」など何か送信すると、登録した本人へ新しい操作メニューを返します。本文を読み取る特別な権限は不要です。以前のメニューは無効になります。スラッシュコマンド `/note` からも開けます。

コマンド一覧はメニューの「コマンド一覧」または `/note_help` で表示します。初期名は次の通りです。記事を扱うコマンドでは記事名の候補から選びます。

| 操作 | 初期コマンド |
| --- | --- |
| メニュー・記事検索／記事一覧 | `/note` ／ `/note_list` |
| 予約一覧／接続状態／同期 | `/note_schedules` ／ `/note_status` ／ `/note_sync` |
| 自動投稿の停止／再開 | `/note_pause` ／ `/note_resume` |
| 下書き作成／本文・公開条件の読み込み | `/note_new` ／ `/note_read` |
| 予約・日時変更／予約取消 | `/note_schedule` ／ `/note_cancel` |
| 今すぐ投稿・更新／削除／タグ変更 | `/note_publish` ／ `/note_delete` ／ `/note_tags` |

PCの「Discord・セットアップ」→「コマンド名の設定」で、各機能の名前を変更できます。保存すると、接続中ならBotを再接続してDiscordへ反映し、停止中なら次回接続時に反映します。日本語の名前も使用でき、重複や不正な名前は保存できません。変更後の名前は「コマンド一覧」にも反映します。

記事の詳細画面の先頭に「記事一覧へ戻る」があります。戻ると検索条件・表示ページを維持し、予約や投稿の処理は実行しません。記事一覧からは「管理メニューへ戻る」で最初のメニューへ戻れます。

「記事一覧」を押すところから、詳細・戻る・管理メニューへの移動まで同じメッセージ内で切り替えます。通常の画面移動で新しい返信や「終了しました」の表示を増やしません。実行した場合は受付と結果を記録として残し、その後に別の新しい操作メニューを出します。実行記録はメニューの切替や無効化で書き換えません。別の操作画面へ移った場合や本人限定画面の有効期限が切れた場合は、前の画面の操作部品を除去します。

コマンド一覧・接続状態には「管理メニューへ戻る」、処理の受付・エラーには記事一覧と管理メニューの戻り先を表示します。投稿・削除・予約の確認を取り消すと、元の記事へ戻ります。日時の入力エラーは記事の操作画面へ戻して再入力できるようにし、新規下書きの入力エラーにも管理メニューへの戻り先を表示します。入力ウィンドウのキャンセルは、開く前の画面を維持します。記事がなくなった場合や一覧が空になった場合も、一覧から管理メニューへ戻れます。

操作できるのは最新の画面だけです。新しい画面を開いた後は、以前のメッセージの操作ボタン・確認ボタン・入力フォームは受け付けません。管理メニューから開き直してください。本文・公開条件が未確認の記事は、先に「本文・公開条件を読み込む」で確認すると投稿・予約・タグ変更が使えるようになります。

タイトルが空欄ではnoteが公開を受け付けません。「noteで編集」でタイトルを入力して下書き保存し、本文・公開条件を読み込み直してください。

- **記事一覧**：すべて／下書き／予約／公開済みの切替、ページ送り、詳細表示。`/note search:検索語` で検索できます。
- **新規下書き**：タイトル・本文・ハッシュタグを入力してnoteへ保存します。
- **画像・長文**：`/note_new` の image に画像、text にUTF-8の .txt 本文を添付できます。画像は見出し画像として保存します。本文内画像はnoteのエディターで挿入できます。
- **内容・公開条件を読み直す**：note側の本文・装飾・素材・価格・公開条件を取得します。未取得の記事はこれを実行してから予約してください。
- **予約・日時変更**：日本時間で日時を入力し、確認画面で予約します。公開済み記事は同じ記事IDの更新として予約します。
- **予約取消**：PC側の予約を解除します。noteの記事は残ります。note自体の予約は二重管理せず、noteの編集画面から変更します。
- **タグ設定**：投稿時のハッシュタグを設定します。
- **今すぐ投稿・更新／noteから削除**：対象と条件を表示して確認します。
- **noteで編集**：スマホのnote本来のエディターを開きます。太字、見出し、画像、音声、埋め込み、ファイル、コミック、目次、リスト、引用、コード、有料エリアなどをnoteの機能で編集できます。

操作の受付と処理完了を区別します。結果は管理チャンネルに通知し、投稿時は公開URLを表示します。登録した本人・サーバー・チャンネル以外の操作は受け付けません。サーバー管理者はDiscordの仕様上、専用チャンネルを閲覧できる場合があります。

「操作履歴」では実行日時・処理内容・記事名・結果・受付番号を確認できます。履歴のページ移動や管理メニューへ戻る操作でも、記録を消したり新しい返信を増やしたりしません。自動の定期同期は履歴の表示から除外し、手動操作の記録を表示します。実行結果を送信した後で接続が切れた場合は、保存済みの送信先IDを使い、記録を重複送信せずに次のメニューの送信を再開します。

実行結果は1回につき1枚の記録カードで表示し、同じ内容を本文へ二重表示しません。その次に、新しい操作メニューを別メッセージで送信します。古い操作メニューだけを取り除き、「終了」の通知は出しません。実行記録の日時・記事名・結果・受付番号は変更しません。

## PCから使う

「投稿管理」と「記事の編集」のタブがあります。編集は広い画面で行えます。装飾や本文素材は最大化したnote本来のエディターで操作します。

保存操作はまずPCの復旧用原稿を保持し、続けてnoteの下書き保存と再読込を行います。note保存待ち・未保存・保存確認済みを区別します。PC内だけの原稿を投稿済みやnote保存済みとは表示しません。ログイン確認後、内容のある既存の未移行原稿もnoteへの保存待ちに登録します。

noteの全記事は既定で1分ごとに同期し、手動同期もできます。全ページ取得を確認できなかった場合は「全件取得未確認」と表示し、取得済み記事を残します。同じ記事はnoteの記事IDで追跡し、再取込みで増殖させません。

note本来の編集画面をPCアプリから開いた場合、最後の投稿操作は公開せず本文・素材・公開設定をアプリへ取り込みます。ウィンドウタイトルの「ストック編集・公開しません」を確認してください。スマホで直接開く通常のnoteエディターでは、noteの投稿操作は実際に公開します。

## 予約と結果確認

日時指定・定期投稿には自動投稿の再開が必要です。過去になった予約は期限超過として残し、起動時にまとめて送信しません。未保存の編集がある間はPC側の処理を保留します。

予約後にnote側の記事が変更された場合は要確認とし、古い本文や公開条件では送信しません。既にnote側で公開された下書きも重複投稿しません。送信結果が不明な場合は自動再送せず、公開結果の確認が必要です。

記事の保存・投稿は、note上の再読込や公開URLを確認して成功にします。失敗時は対象と理由を表示します。Discordの受付要求は永続化され、連打・同じ要求の再送は重複実行を防ぎます。処理途中のアプリ終了は結果未確認として保全します。

## データと配布

データ・専用ブラウザー・暗号化トークンは展開先の `data` にあります。既存DBは初回移行時にバックアップします。バックアップする場合はアプリを終了して data 全体をコピーしてください。別Windows利用者ではトークンや公開設定の再取得が必要です。

配布には未使用のソースZIPを使ってください。使用済み data を他人へ渡さないでください。診断ログは既定OFFで設定から切替できます。本文・Cookie・トークンを診断ログへ出しません。処理履歴と必要な失敗通知は診断OFFでも残ります。

## CLI

`main.py --cli <操作> --id <ID> --input <JSONファイル>` でGUIと同じデータを操作できます。新しい操作は `sync_articles`、`save_note_draft`、`refresh_article`、`schedule`、`cancel_schedule`、`publish_note`、`delete_note`、`tags`、`job` です。非同期操作は job_id を返すので `--cli job --id <job_id>` で結果を確認します。キュー処理にはPCアプリの起動が必要です。

`publish_note` と `delete_note` の入力には、直前の get 結果にある updated を confirmed_updated として指定します。従来の delete はnote記事を削除する操作に変更していません。noteに紐づく記事は明示的な delete_note を使います。

実測済みの範囲と未検証事項は VALIDATION.md を参照してください。
