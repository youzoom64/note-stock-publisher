noteストックの使い方

PCでnoteの記事と投稿予定を管理し、スマホのDiscordから確認・予約できるアプリです。

予約投稿には、PCの電源・noteストックの起動・ネット接続が必要です。
予約を登録した後は、自動投稿が「動作中」になっていることを確認してください。

最初にすること

  1. 配布ZIPを展開して、start.cmdを開きます。
  2. PCの設定からnoteにログインします。
  3. Discord・セットアップでDiscordを連携します。PCだけで使う場合は後から設定できます。
  4. noteの全記事を同期を押し、記事一覧を取り込みます。
  5. 記事を選んで投稿予定を設定し、自動投稿を開始を押します。

スマホで操作する

Discordの専用チャンネルで記事一覧を開きます。記事を押すと、その記事の本文・公開条件を取得します。

PCで操作する

記事のダブルクリックで本文・公開条件を取得します。右側の投稿設定で方法と日時を選びます。

初回セットアップ

起動する

ZIPの中身を、書き込みできるフォルダーへすべて展開してからstart.cmdを開きます。初回はPython・専用環境・必要なライブラリとブラウザーの準備を行います。準備が終わるまで画面の案内に従ってください。

2回目以降もstart.cmdで起動します。すでに起動している場合は、その画面を開きます。

noteにログインする

  1. 設定を開き、自分のnote IDとログイン方法を設定します。note IDは、プロフィールURLのnote.com/に続くIDです。
  2. ログイン・接続確認を押し、専用ブラウザーでログインします。
  3. GoogleログインではGoogleでログインを選びます。本人認証がある場合は、ご自身で完了してください。
  4. ログイン画面の案内に従って専用ウィンドウを閉じ、アプリに接続確認済みと表示されることを確認します。

Discordを連携する

  1. 初回のDiscord連携しますか？で利用を選ぶか、Discord・セットアップを開きます。
  2. 自動で設定か手動で設定（HTML手順を開く）を選びます。
  3. 自動設定では、専用サーバーの新規作成または既存サーバーへの導入を選び、画面に従ってDiscordにログインします。二段階認証やCAPTCHAはご自身で完了してください。
  4. 手動設定では、案内に沿ってBotを導入し、BotトークンとサーバーIDを設定します。Discordの手動セットアップ手順を開く
  5. 専用の管理チャンネルと操作メニューが用意されたら、スマホのDiscordからそのチャンネルを開きます。

利用できるのは登録した本人・サーバー・チャンネルです。Discordのサーバー管理者は、権限によって管理チャンネルを閲覧できる場合があります。Botトークンをチャンネルへ投稿しないでください。

Discordで記事を操作する

記事を開いて本文を読む

操作メニュー→記事一覧→記事タイトル

一覧は1ページ15件です。種類の切り替え、検索、前へ・次へで目的の記事を探します。

未取得の記事を押すと本文取得中が表示され、取得後に同じ記事画面へ本文と公開条件を表示します。長い本文には全文のarticle.txtが付きます。記事一覧を開いただけで、全記事の本文を取得することはありません。

記事一覧へ戻るで、元のページ・検索条件へ戻れます。古い画面のボタンが操作できなくなった場合は、最新の操作メニューから開き直してください。チャンネルに「メニュー」と送るか、/noteでもメニューを開けます。

新しく下書きを作る

新規下書きでタイトル・本文・ハッシュタグを入力します。処理結果でnoteへの保存を確認してください。保存だけでは公開されません。画像や長い本文を添付するときは/note_newの画像・テキスト添付欄を利用できます。

本文・公開条件・タグを変更する

装飾、画像、有料エリアなどはnoteで編集からnoteの編集機能を使います。変更後は内容・公開条件を読み直すでアプリへ反映してください。投稿時のタグはタグ設定で変更できます。

スマホで直接開いた通常のnote編集画面では、最後の投稿操作で実際に公開されます。下書きのまま残したいときは、noteの下書き保存を使ってください。

今すぐ投稿・更新する

記事の本文・公開条件を確認して今すぐ投稿・更新を押します。記事名と条件を確認して実行してください。公開済みの記事は同じ記事の更新として扱います。結果に公開URLが表示されたら、必要に応じて記事を開いて確認できます。

noteから記事を削除する

記事画面のnoteから削除を押し、確認画面で対象を確認して実行します。note上の記事自体を削除する操作です。投稿予定だけを解除したい場合は予約取消を使います。

「受付」と「完了」は別です。処理結果が失敗・結果未確認のときは、理由とnote上の状態を確認してから次の操作を行ってください。

日時を指定して投稿する

  1. 記事画面で予約・日時変更を押します。
  2. カレンダーで月と日付を選びます。
  3. 時を選択と分を選択で時刻を選びます。分は5分刻みで選べて、−1分・＋1分で1分ずつ調整できます。
  4. この時刻で確認を押し、記事名と日本時間の年月日・時刻を確認します。
  5. この日時で予約するで登録します。予約一覧や記事画面で投稿予定を確認してください。
  6. 自動投稿が停止中なら、PCの自動投稿を開始またはDiscordの自動投稿 停止／再開から再開します。

「日時指定待ち」は、日時指定の予約が入っている状態です。
その時刻に投稿するには、自動投稿が動作中で、PCとアプリが起動している必要があります。

変更・取消

日時を変えるときは同じ記事で予約・日時変更を開きます。取り消すときは予約取消を使います。取消後もnoteの記事は残ります。公開済みの記事は日時指定予約の対象ではなく、今すぐ投稿・更新で更新します。

予約時刻を過ぎたら

一時停止・アプリ終了・スリープなどで時刻を過ぎた予約は期限超過になります。再開時にまとめて公開せず、再予約が必要です。過去の日時は新しい予約として受け付けません。

標準のDiscordカレンダーにHTTPS中継の設定は不要です。別の予約Web画面を使う場合だけ、追加の接続設定が必要です。HTTPS接続の自動作成は、この版の標準セットアップには含まれていません。

定期投稿とキュー

毎日などの決まった投稿枠へ、記事を順番に並べたいときに使います。曜日と投稿時刻はPCの設定で変更します。

投稿時刻を変更する

PCの設定で投稿時刻（日本時間）の時刻欄を押すと、その直下に小さな選択パネルが開きます。左の時（00〜23）と右の分（00〜59）をクリックして選び、決定を押すと保存されます。

現在で現在の時・分を選べます。Escキーやパネルの外側を押して閉じた場合は、選択途中の時刻を保存しません。数字を直接入力することもできます。

  1. PCで記事にチェックを付け、キューへ追加を押します。表示順で既存キューの末尾へ追加されます。
  2. 投稿待ちを投稿予定順で表示して、順番と投稿予定を確認します。
  3. 順番を変えるときは、黄色のキュー記事をドラッグします。移動先の投稿日時が表示されます。
  4. 自動投稿を開始すると、設定した曜日・時刻の枠ごとにキューから投稿します。

茶色の日時指定記事は、個別の日時を指定した記事です。キューを並べ替えても、その指定時刻を保持します。

途中に入れたいとき

割り込みで開始日を指定したり、キュー記事の定期投稿の日に差し込む…で日を選んだりできます。後続のキューは順番を維持して次の投稿枠へ移ります。キューから外すときはキュー解除を使います。

キュー追加・日時変更・タグ変更はPC内の設定として登録します。それだけでは本文を取得しません。記事内容の確認は、記事を開く操作または明示的な読み直しで行ってください。

PCの画面で使う

操作使い方
記事の種類・検索一覧上部で下書き・投稿待ち・投稿済み・要確認などを切り替え、検索欄に題名や本文の言葉を入力します。
本文を取得対象記事をダブルクリックします。取得済みなら保存した内容を表示します。最新の編集内容を確認したい場合は、note側の内容を読み直してください。
日時指定の予約投稿方法を「日時を指定して投稿」にし、未来の投稿日時を選んで「投稿設定を保存」を押します。
定期投稿のキュー投稿方法を「定期投稿のキューへ追加」にして保存するか、一覧のチェックと「キューへ追加」を使います。
下書きのまま保持投稿方法を「下書きとして保存（投稿未定）」にして保存します。
noteと同期「noteの全記事を同期」で一覧を更新します。標準の自動同期間隔は60分です。間隔は「設定」で変更できます。
noteで編集専用のnote編集画面を開きます。「ストック編集・公開しません」と表示される画面では、最後の投稿操作で本文・公開条件をアプリへ取り込みます。
公開結果を確認送信結果が不明な記事などで使います。確認前に同じ記事の投稿を繰り返さないでください。
下書きに戻す要確認の記事に表示される「下書きに戻す」で、アプリ内の管理状態を戻します。これだけでnote上の公開記事を非公開にする操作にはなりません。

記事一覧の同期と、本文・公開条件の取得は別の操作です。一覧の同期では各記事の状態や更新情報を取り込みます。

状態表示の意味

「管理」はnoteストック内の状態、「note」はnote側で確認した状態です。失敗などがある場合は、両方を見て確認してください。

表示意味・次の操作
下書き投稿予定を決めていない状態です。必要に応じて内容確認、予約、キュー追加を行います。
定期投稿待ち定期投稿のキューに入っています。投稿枠と並び順を確認してください。
日時指定待ち個別の予約が登録されています。投稿予定と自動投稿の動作状態を確認してください。
投稿中投稿処理を実行中です。結果が出るまで待ちます。
投稿済み公開結果を確認した状態です。公開URLから記事を確認できます。
期限超過停止・休止中などに予約時刻を過ぎました。未来の日時で再予約するか、内容を確認して今すぐ投稿します。
失敗処理が完了しませんでした。記事画面や操作履歴に表示される理由を確認します。
ログイン確認待ちnoteのログイン確認が必要です。設定から接続を確認します。
結果未確認送信した処理の結果を確定できていません。公開結果を確認してから次の操作を選びます。
変更あり・要確認内容・公開条件などの再確認が必要です。最新の内容を読み直し、投稿予定を確認します。
noteで編集中専用の編集・取り込み処理中です。画面の案内に沿って完了または中止します。
noteで予約済みnote自体の予約機能で保存されています。日時の変更や取消はnoteの編集画面で確認します。
noteへ反映済み（非公開）note側の非公開条件で反映を確認した状態です。公開条件はnoteの画面で確認します。

困ったとき

予約したのに投稿されない

PCの電源・スリープ状態・アプリの起動・ネット接続を確認します。次に自動投稿が動作中か、指定した年・日付・日本時間の時刻が正しいかを確認してください。記事が「失敗」「期限超過」「結果未確認」などになっている場合は、その理由に沿って再予約や結果確認を行います。

記事が「失敗」になった

記事の「理由」と「操作履歴」を確認します。1件の失敗だけで他の記事の自動投稿を停止するとは限りません。ログイン切れなどでは自動投稿を停止するため、上部の動作状態も確認してください。投稿結果が不明な場合は、note上の状態や「公開結果を確認」を使ってから再操作します。

Discordのボタンが応答しない・古い画面だと言われる

PCとアプリが起動しているか、Discord連携が接続済みかを確認します。古いメニューは新しい操作で無効になります。最新の管理メニューを使い、必要ならチャンネルに「メニュー」と送るか、/noteを実行してください。

本文が表示されない

未取得の記事は、PCではダブルクリック、Discordでは記事タイトルを押して取得します。「本文取得中」の後に本文が表示されます。長文はarticle.txtも確認してください。noteで編集した後は、内容・公開条件を読み直します。

「note保存待ち」「PCに仮保存」と表示される

PC内には保存されていますが、noteへの保存はまだ完了していません。処理結果とログイン状態を確認してください。PCへの仮保存だけで、noteに記事が保存済みになったり公開されたりするわけではありません。

削除できたか分からない

操作履歴の結果と、noteの「自分の記事」の一覧を確認します。削除処理の途中で応答が途切れた場合は、noteに記事が残っているかを確認してから再操作してください。予約だけの解除には「予約取消」を使います。

「タイトルが未入力」と表示される

noteの編集画面でタイトルを入力して下書き保存し、本文・公開条件を読み直してください。

noteのログインが切れた

PCの「設定」から「ログイン・接続確認」を実行します。追加の本人認証が出た場合は完了してください。接続確認後は、自動投稿の動作状態と投稿予定を再確認します。

終了・データの保管

ウィンドウを閉じるとき

右上の「×」は通知領域（タスクトレイ）への収納です。自動投稿とDiscord連携は続きます。通知領域のnoteストックのアイコンをクリックすると、画面を開きます。

完全に終了する場合は、通知領域のアイコンを右クリックして「終了」を選びます。完全終了中・PC停止中・スリープ中は予約投稿もDiscord操作も動きません。

バックアップ・移動

アプリを完全に終了してから、アプリのフォルダー内にあるdataフォルダー全体をコピーしてください。記事・予約・操作履歴・専用ブラウザーなどのデータが保存されています。

別のWindows利用者や別PCへ移したときは、ログインや公開条件の再取得が必要になる場合があります。他人へアプリを渡すときは配布用ZIPを使い、ご自身のdataを含めないでください。

ログを確認する

data/logsに起動・終了や主な処理結果の診断ログがあります。ログは次回のアプリ起動時に初期化されるため、調査用に残す場合は再起動前にコピーします。ログの保存は「設定」の診断ログを保存するで切り替えられます。記事の操作履歴は別に保存されます。
